# Security policy

## Reporting a vulnerability

Please do not open a public issue for a suspected vulnerability. Use GitHub's
private vulnerability reporting feature in the repository Security tab.

Include the affected version, impact, reproduction steps, and any suggested fix.
Maintainers should acknowledge a report within five business days. This response
target is a goal, not a service-level agreement.

## Supported versions

Until the first stable release, only the latest published version receives security
fixes.

## Scope reminder

Security findings produced by pgSecureCheck require human review. A clean report
does not establish that a PostgreSQL deployment is secure or compliant.
